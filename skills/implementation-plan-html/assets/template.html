Risks & decisions

Decision

Refresh inline vs. middleware. Going with inline because the call-site count is small and middleware would require touching every route.

Risk

Refresh loop on bad token. Mitigation: cap retries at 1 and surface a typed error.

OptionProsCons
Inline refreshMinimal churnDuplicated per call-site
MiddlewareCentralizedTouches every route

Testing

  • Unit: expired access token triggers refresh; valid token does not.
  • Integration: end-to-end login → expire → call → refreshed call succeeds.
  • Manual: log in, sleep token, hit protected route.
